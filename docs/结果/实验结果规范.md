# 人类可读实验结果规范

本规范用于一个稳定 Experiment ID 的当前结果页。页面服务于研究判断，不承担运行日志、完整 provenance 或阶段综合报告的职责。

## 写作合同

- 默认长度为 **1–3 屏**；超过后应删减、链接下沉，或明确升级为阶段性综合报告。
- 标题必须使用 `EXP-XXX｜中文实验标题`；日期、seed 和重跑编号不是主要身份。
- 结论优先，表格和关键图优先；正文只保留理解结果所需的信息。
- 明确区分实验状态、证据层级、解释和研究决策；Draft 文档不等于人类已接受结论。
- surrogate、proxy、solver replay 与 physical validation 不得互相替代。

正文不复制完整 shell command、CUDA/package 版本、stdout、逐 epoch 日志、文件生成流水、Agent 执行步骤、全量 provenance、无关配置或 raw metric dump。它们只在“证据入口”中向下链接。

## 统一模板

```markdown
# EXP-XXX｜中文实验标题

## 一句话结论

用一到两句话直接回答研究问题，并注明最重要的证据边界。

## 核心结果

优先给出一张紧凑表格；只保留决定结论的指标。必要时加入一张关键图。

## 与基线相比

说明 baseline 身份、同协议可比性、改善或退化，以及统计或重复实验边界。

## 解释与限制

分别说明科研含义和不能外推的范围；失败、单 seed、proxy 或缺失 gate 必须显式写出。

## 决策

明确选择：继续 / 停止 / 修改 / 需要额外验证。写出对象和下一 gate，不写任务流水。

## 关键设置

只保留理解结果必须知道的数据身份、split、输入输出、主指标、seed/replay 规模和验证后端。

## 证据入口

- experiment spec
- config
- runs
- raw metrics
- figures
```

## 最小质量门

| 检查项 | 通过条件 |
|---|---|
| 问题可见 | 读完标题和一句话结论即可知道实验回答什么 |
| 基线明确 | baseline 身份和协议可比性可核查 |
| 主张受限 | 单 seed、surrogate、replay、物理验证和阻塞状态没有混用 |
| 决策可执行 | 明确继续、停止、修改或额外验证，以及下一 gate |
| 证据可追溯 | spec、config、run、metrics 和 figures 有入口，不在正文复制原始内容 |
| 页面够短 | 普通实验保持 1–3 屏；长篇内容下沉到证据页或综合报告 |

结果页的导航入口见[当前结果](README.md)，详细证据保留在[实验与证据库](../results/README.md)，正式 Experiment ID 以 [`experiments/registry.yaml`](https://github.com/fangtoast/phc2d/blob/main/experiments/registry.yaml) 为准。
