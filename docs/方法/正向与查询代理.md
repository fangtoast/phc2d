# 正向与查询代理

Forward 与 Query 都近似结构到光子能带的映射，但一个输出完整谱矩阵，另一个在给定 physical-k 条件下回答查询。两者可以共享结构编码思想，不能共享未声明的输出 shape 或评估协议。

## 1. 问题与输入输出

Full-Wh 学习

$$
F_\theta:x\mapsto \widehat Y,qquad
\widehat Y\in\mathbb R^{N_k\times N_b}.
$$

Query 学习

$$
Q_\phi:(x,\mathbf k_q)\mapsto \widehat{\mathbf y}_q,qquad
\widehat{\mathbf y}_q\in\mathbb R^{N_b}.
$$

Query 的结构 split 必须先冻结，再在 split 内展开 k 点，否则同一结构会通过不同 query 泄漏到 train/test。

## 2. 模型映射与公式

### Full-Wh 模型族

| 模型族 | 计算观点 | 适用角色 |
|---|---|---|
| MLP / ResMLP / Gated ResMLP | 展平结构后做全局回归；残差块改善深层优化 | 固定输入拓扑基线 |
| CNN / lifted CNN / ConvNeXt | 局部卷积逐层聚合空间特征 | 局部几何基线与升级模型 |
| FNO / TFNO | 在 Fourier 空间对保留模态施加可学习算子 | 周期全局耦合 |
| Mixer | 分别混合空间 token 与 channel | 非卷积全局基线 |
| dual-lane operator | 联合编码 binary/graded，并显式接收 lane | 双路线联合建模 |

FNO 的一层可写成

$$
v_{\ell+1}(\mathbf r)=\sigma\!\left(
W_\ell v_\ell(\mathbf r)+
\mathcal F^{-1}\!\left(R_\ell\odot\mathcal F(v_\ell)\right)(\mathbf r)
\right).
$$

`fno2d_band_v2` 在输出端保留 band-aware 结构；TFNO 对频谱权重进一步因式分解。升级模型使用独立 registry name 与 checkpoint identity，不覆盖 baseline。

### Query 模型族

- `mlp_query`：结构特征与 k 坐标拼接的低复杂度基线；
- `deep_onet_query_v2`：branch 编码结构，trunk 编码 $\mathbf k$，再组合 latent 表示；
- `fno2d_query_v2`：频谱结构编码器加 query 条件头。

DeepONet 风格组合可抽象为

$$
\widehat y_b(x,\mathbf k)=
\sum_{j=1}^{p}B_{b,j}(x)T_{b,j}(\mathbf k)+c_b.
$$

项目中的名称表示 task-adapted 实现；模型身份以 registry 与 checkpoint metadata 为准。

## 3. 损失与指标

基础训练可在标准化目标上使用 MSE：

$$
\mathcal L_{\mathrm{MSE}}=\frac1M\sum_j(\widehat y_j-y_j)^2.
$$

band-aware 目标还可加入相对误差、band ordering 与沿 k 方向的平滑项：

$$
\mathcal L=\lambda_m\mathcal L_{\mathrm{MSE}}
+\lambda_r\mathcal L_{\mathrm{rel}}
+\lambda_o\mathcal L_{\mathrm{order}}
+\lambda_s\mathcal L_{\mathrm{smooth}}.
$$

训练 loss 驱动参数更新，validation metric 选择 checkpoint，held-out test 只在冻结后评估。三者不能互换。

## 4. 实际 tensor shape

| 合同 | 输入 | 输出 |
|---|---|---|
| V2 10k Full-Wh | `x[B,...]` | `Wh[B,31,10]` |
| 全胞 Full-Wh | `grid[B,H,W]` 或 `grid[B,1,H,W]` | `Wh[B,81,10]` |
| Query materialized | `structure[B,...]`, `k_coordinate[B,2]` | `bands[B,N_b]` |
| dual-lane | 上述 grid 加 lane id | 同一 target shape，lane 指标另行分组 |

这些数字只描述当前正式数据；训练器从 dataset contract 构造 `input_shape`、`target_shape` 与可选 `k_points`。

## 5. 核心源码

实际 band-aware loss 不写死 band 或 k 点数量，而是从 tensor 维度判断可用项。以下节选核对版本为 `c347845`，完整实现见 [`forward/runner.py`](https://github.com/fangtoast/phc2d/blob/c347845/src/phc2d/forward/runner.py)。

```python
def _band_aware_loss(prediction, target, *, torch, floor, weights):
    mse_weight = float(weights.get("mse_weight", 1.0))
    relative_weight = float(weights.get("relative_weight", 0.5))
    ordering_weight = float(weights.get("ordering_weight", 0.05))
    smoothness_weight = float(weights.get("smoothness_weight", 0.02))
    loss = mse_weight * torch.mean(torch.square(prediction - target))
    if int(prediction.shape[-1]) > 1:
        pred_main = prediction[..., 1:]
        target_main = target[..., 1:]
        denom = torch.clamp(torch.abs(target_main), min=float(floor))
        loss = loss + relative_weight * torch.mean(
            torch.abs(pred_main - target_main) / denom
        )
        ordering = torch.relu(prediction[..., :-1] - prediction[..., 1:])
        loss = loss + ordering_weight * torch.mean(ordering)
    if prediction.ndim >= 3 and int(prediction.shape[-2]) > 1:
        smooth = prediction[..., 1:, :] - prediction[..., :-1, :]
        loss = loss + smoothness_weight * torch.mean(torch.square(smooth))
    return loss
```

模型由 registry 按稳定名称构建；完整入口见 [`models/registry.py`](https://github.com/fangtoast/phc2d/blob/c347845/src/phc2d/models/registry.py)，不要从类名猜 checkpoint 兼容性。

## 6. 配置与最小命令

V2 Query 公平协议明确冻结数据 hash、split、模型候选与 seed：

```yaml
fair_selection:
  expected_split_sizes: {train: 6875, val: 2500, test: 625}
  selection_split: val
  final_evaluation_split: test
  selection_metric: query_mre_bands_2_10_pct
  require_exact_seed_count: 3
model:
  candidates: [mlp_query, deep_onet_query_v2, fno2d_query_v2]
```

```powershell
python -m phc2d.cli forward benchmark --config configs/research/a1_forward_fair_v1.yaml
python -m phc2d.cli query benchmark --config configs/research/a1_query_fair_v1.yaml
```

只想检查最小链路时，使用[第一次正向预测](../开始/第一次正向预测.md)中的 synthetic smoke；它不产生物理证据。

## 7. 产物与证据边界

训练 run 应写出 resolved config、模型/工厂 identity、checkpoint、history、validation 选择记录、test metrics、逐 band 诊断和 runtime。用于 inverse 排序时还要记录候选池、K、Top-M、主/交叉代理与 `surrogate_replay_gap`。

held-out surrogate 结果能够证明特定数据合同上的预测误差；不能证明 MPB 标签无误、跨数据代泛化、逆向候选真实有效或 Meep 有限阵列性能。当前入口见[V2 10k 正式结果](../results/V2-10k正式结果.md)和[新全胞数据正式结果](../results/全胞数据正式结果.md)。
