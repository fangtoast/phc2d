# 模型目录

“模型存在”至少可能指实现文件存在、registry 可见、训练可运行、checkpoint 可用或已有正式证据。这些状态不可互换。当前清单应由 CLI、机器可读 inventory 与日期报告共同确认。

## 必查家族

| 家族 | 常见任务 | 核对重点 |
| --- | --- | --- |
| MLP / ResMLP | 正向频带或展平目标 | 输入输出表示、残差结构、参数量 |
| CNN | 栅格结构到频带或场 | 空间 shape、下采样与输出头 |
| FNO | 算子学习、频带或场 | mode、分辨率策略、坐标与边界 |
| DeepONet | branch/trunk 查询 | branch 表征、query 坐标、配对方式 |
| U-Net | 稠密场预测 | 编解码层级、skip、输出分量 |
| inverse generators | 条件候选生成 | 条件定义、采样预算、代理排序与回放 |

混合条件生成器不应被写成 cVAE 或 diffusion；adapted PINO 也不应被包装成另一个独立、忠实复现的 PINO 架构。

## 建议身份字段

```yaml
registry_name: mlp
implementation: src/phc2d/...
config: configs/research/...
architecture_fingerprint: ...
checkpoint: ...
dataset_id: ...
training_status: not_run | smoke | completed
validation_status: none | surrogate | real_solver
evidence_report: docs/results/...
```

报告项目级或“完整覆盖”时，必须对照 `phc2d models list`、`docs/reports/phc2d_model_inventory_v1.yaml` 和 `src/phc2d/inverse` 中未注册方法，并明确没有可采纳结果的家族。

## 结果用语

- `implemented`：仅说明代码存在。
- `registered`：仅说明可由 registry 发现。
- `trained`：说明某个明确数据与配置身份完成训练。
- `surrogate-validated`：只说明代理 held-out 评估。
- `solver-replayed`：说明候选经过真实 MPB/Meep 回放。
- `accepted`：必须同时满足对应协议、环境和证据门槛。

模型方法解释见[正向与查询代理](../方法/正向与查询代理.md)和[逆向设计与物理回放](../方法/逆向设计与物理回放.md)。
