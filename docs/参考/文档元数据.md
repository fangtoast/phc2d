# 文档元数据

本页定义文档站用于区分正式结果、历史记录和研究计划的元数据。它只约束文档分类，不改变实验、模型或物理验证状态。

## 正式结果字段

`page_type: evidence` 的页面必须同时声明：

| 字段 | 允许值或内容 | 作用 |
|---|---|---|
| `dataset_scope` | 稳定数据身份，如 `v2_10k_wh31x10` | 防止不同 shape、split 或 lineage 混表 |
| `evidence_level` | `data_acceptance`、`surrogate_held_out`、`solver_replay`、`physical_validation` | 表明结果属于哪一级证据 |
| `evidence_status` | `completed`、`pilot`、`blocked`、`historical` | 表明协议完成度，不代表人工接受 |
| `validation_backend` | `surrogate_only`、`wsl_mpb`、`wsl_meep`、`mixed`、`not_applicable` | 区分代理评估与真实求解器 |
| `source_artifacts` | 一个或多个 run、manifest、metrics 或索引路径 | 提供可追溯来源 |

示例：

```yaml
dataset_scope: v2_10k_wh31x10
evidence_level: solver_replay
evidence_status: completed
validation_backend: wsl_mpb
source_artifacts:
  - runs/20260706/example/results.json
```

`status: draft` 表示页面尚待人类接管；它与 `evidence_status: completed` 不冲突。前者是文档审阅状态，后者是所记录协议的状态。

## 计划生命周期字段

`page_type: plan` 的页面必须声明：

| 字段 | 允许值或内容 | 作用 |
|---|---|---|
| `plan_state` | `active`、`completed`、`superseded`、`reference` | 说明计划在当前路线中的角色 |
| `effective_date` | ISO 日期 | 支撑时间线排序 |
| `superseded_by` | 新计划路径或 `null` | 记录取代关系 |
| `related_results` | 结果页面路径列表，可为空 | 把计划与实际证据连接起来 |

计划中的勾选、命令和阈值不证明任务已经执行。状态冲突时，仍按“运行制品与求解器输出高于代码、报告和计划”的顺序判断。

## 审计

严格文档审计会验证字段存在性和枚举值：

```bash

```
