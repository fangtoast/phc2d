# 系统架构

phc2d 把物理数据、学习模型、逆向搜索和证据报告放在一个统一仓库中，但各层不共享未经声明的结论。稳定公共能力位于 `src/phc2d`，研究配置位于 `configs/research`，实验说明位于 `experiments/research`。

```mermaid
flowchart LR
    A["结构参数与材料分布"] --> B["MPB / Meep 数据生成"]
    B --> C["规范化数据集与 metadata"]
    C --> D["Forward / Query / Field 模型"]
    D --> E["held-out 代理评估"]
    D --> F["逆向候选生成与排序"]
    F --> G["真实 MPB / Meep 回放"]
    E --> H["日期化证据报告"]
    G --> H
    H --> I["稳定主题文档"]
```

## 模块边界

| 层 | 主要职责 | 不应承担的职责 |
| --- | --- | --- |
| 数据与 schema | 表征、metadata、split、归一化和 shape | 模型效果结论 |
| 求解器适配 | MPB/Meep 调用、输入输出转换、物理诊断 | 将 surrogate 结果冒充物理验证 |
| 模型与训练 | registry、网络、损失、训练和评估 | 硬编码数据 shape 或运行目录 |
| 逆向设计 | 候选生成、代理排序、真实回放编排 | 混合 surrogate 与 replay 指标 |
| 报告与文档 | 索引、证据边界、可复现入口 | 覆盖原始运行产物或改写历史记录 |

## 依赖边界

`torch`、`h5py`、MPB 与 Meep 必须保持可选或延迟导入。基础命令帮助不应因为训练或求解器依赖缺失而失败。正式 MPB/Meep 验收只认 WSL `Ubuntu` 中的 conda `meep_env`；Windows 本地运行只能作为编辑或紧急诊断。

## 数据与证据流

数据通过 metadata 描述输入表征、目标、shape、单位与 split。训练运行写入标准运行目录，日期报告再从运行产物提炼结论。稳定主题页只吸收跨日期仍成立的规则，并链接到证据页，不复制易漂移数字。
