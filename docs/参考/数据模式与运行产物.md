# 数据模式与运行产物

数据文件必须能够回答：样本表示什么、输入和目标如何排列、shape 从何而来、单位是什么、怎样划分，以及它由哪个生成协议产生。模型、损失、指标和绘图都从这些契约读取 shape。

## 最小数据身份

| 字段组 | 至少记录 |
| --- | --- |
| 来源 | 生成器、协议、代码版本、创建时间、SHA-256 |
| 表征 | 输入表示、目标表示、维度顺序、dtype、单位 |
| 几何与物理 | 晶格约定、材料参数、边界条件、k 路径或采样域 |
| 划分 | train/validation/test 定义、seed、泄漏检查 |
| 归一化 | 统计量来源、应用轴、逆变换方式 |
| 质量 | NaN/Inf、范围、重复项、求解失败与排除理由 |

`rho_wedge -> Wh` 是一个基线任务，不是项目唯一任务。任何使用 `DataRepresentationSpec` 或 `TargetSpec` 的流程都应在运行前打印或保存解析后的契约。

## 标准运行目录

```text
runs/{yyyymmdd}/{experiment_id}_{YYYYMMDDHHmm}/
├── run.log
├── run.meta.json
├── config.resolved.yaml
├── results.json
├── metrics.json
├── history.csv
└── figures/
```

按任务需要还可以保存 checkpoint、候选、回放输入输出和诊断数组，但不得用精简报告替代原始产物。

## 指标分区

- 训练与评估：`train_time_s`、`eval_time_s`、`inference_time_per_sample_ms`、throughput。
- 候选生成：`candidate_sampling_time_s`、`surrogate_ranking_time_s`。
- 物理回放：`mpb_replay_time_s` 与求解失败统计。
- 总成本：`wall_time_total_s`，并说明并行度与硬件。

逆向任务至少区分 `best_of_k_surrogate_mre`、`best_of_k_replay_mre` 与 `surrogate_replay_gap`。详细操作见[数据生成](../指南/数据生成.md)和[逆向候选与回放](../指南/逆向候选与回放.md)。
