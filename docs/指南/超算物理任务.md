# 超算物理任务

统一 campaign 控制面把数据生成分为 `plan → shard/array → finalize → status → audit`。当前 full-cell band 参考适配器已实现；其他任务族的适配器登记不等于完成多节点迁移。

## Plan

规划阶段只读取配置和输入，冻结：

- campaign id、输入与输出；
- 样本范围和 shard 边界；
- solver 与结构合同；
- 平台资源、并发和超时；
- plan hash 与预期产物。

Plan 不提交作业，也不证明资源已分配。

## Shard 或 array

每个分区只负责自己的样本范围，写入独立临时产物和状态。失败必须显式记录；不要以空数据代表连接、解析或求解失败。

## Finalize

Finalizer 先验证分区无遗漏、无重叠、plan hash 一致且失败数为零，再由单写者合并并原子发布。未完成检查时保留 incomplete 产物，便于恢复和审计。

## Status 与 audit

Status 汇总计划、调度和分片状态；audit 复核范围、hash、schema、求解器 provenance 和发布结果。它们不触发新的物理计算。

## 平台边界

资源参数从平台配置读取，不把 core 数、队列名或 GPU 数硬编码到 runner。真实提交和长时间 MPB/Meep 计算需要单独授权；dry-run 只能证明编排合同。

参考配置和命令见[CLI 与配置](../参考/CLI与配置.md)。
