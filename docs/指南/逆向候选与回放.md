# 逆向候选与回放

逆向流程按 stage 运行。缺少冻结 checkpoint、目标 manifest、候选身份或 real-MPB 环境时，不得跳过前置门直接声明结果。

## 冻结输入

1. 目标 manifest 和目标分层策略；
2. generator checkpoint、seed 与候选数 K；
3. 结构 codec 和 hard/soft decode 规则；
4. 主排序代理、交叉代理、normalization 和目标 band；
5. Top-M、去重与最小距离规则；
6. real-MPB solver 配置和缓存策略。

## 生成候选

从逆向命令帮助查看可用 stage：

```bash
python -m phc2d.cli inverse --help
python -m phc2d.cli inverse benchmark --help
```

生成产物必须保留 target、seed、latent、candidate id、结构族、codec 参数和 checkpoint identity。不要只保存最终 Top-1。

## 健康检查与排序

先检查结构合法性、重复、最近邻距离、多样性和有效候选数，再运行冻结代理排序。任何失败都写入结果，而不是删除后把分母改成成功数。

输出至少区分：

- 生成前 K；
- 合法候选数；
- 去重后候选数；
- surrogate Top-M；
- 交叉代理分歧；
- 候选采样与排序时间。

## real-MPB replay

Replay 必须在 WSL `Ubuntu` + `meep_env` 或协议允许的物理环境执行，并逐例记录 solve 状态。最终表分别给出 `best_of_k_surrogate_mre`、`best_of_k_replay_mre` 和 `surrogate_replay_gap`。

## 停止条件

以下任一情况都应停止并保留 `blocked` 或失败状态：

- checkpoint/data identity 不匹配；
- 候选健康门失败；
- 排序依赖未准入的 Field/PINO 分支；
- real-MPB 环境或授权缺失；
- replay 失败被错误解释为空结果。

当前证据和各 stage 状态见[Inverse 结果索引](../results/README.md#inverse-results)。
