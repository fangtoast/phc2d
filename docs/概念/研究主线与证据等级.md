# 研究主线与证据等级

`phc2d` 的主线是 **Replay-Calibrated Hierarchical Inverse Design**：先用真实求解器形成可追溯数据，再用代理模型降低搜索成本，最后把少量候选交还真实求解器裁决。

```mermaid
flowchart LR
    A["结构与材料"] --> B["real-MPB / Meep 数据"]
    B --> C["Full-Wh / Query / Field 代理"]
    C --> D["多候选生成"]
    D --> E["合法性、多样性与代理排序"]
    E --> F["real-MPB replay"]
    F --> G["物理证据与失败分析"]
```

## 为什么需要分层

真实求解器准确但昂贵；代理模型快速但可能在训练分布之外失真；生成器还可能利用代理漏洞。因此项目不把一次代理误差下降直接视为逆向设计成功，而是把每一层的输入、输出和 gate 分开记录。

## 证据等级

| 状态 | 证明什么 | 不能证明什么 |
|---|---|---|
| 计划 | 研究问题、方案和 gate 已定义 | 代码或实验已经完成 |
| 已实现 | 接口或算法路径存在 | 数值有效、训练完成 |
| smoke | 最小链路可运行 | 模型性能或物理正确性 |
| pilot | 小范围现象和可行性 | 大样本、跨 seed 或普遍结论 |
| surrogate result | 冻结协议下的代理指标 | 真实求解器目标已满足 |
| diagnostic / proxy | 发现敏感性、风险或排序信号 | 可以替代 headline 或 replay |
| real-MPB replay | 指定候选和协议的真实求解结果 | 其他数据、结构族或任务同样成立 |
| formal acceptance | 预先定义的对应 gate 已通过 | 项目全部研究问题已完成 |

Field/PINO 还需额外注意：较低 PDE residual 并不自动意味着频率更准确，也不自动意味着其可以进入 inverse reranking。

判断“现在做到了哪里”时依次查看：

1. 实际 run、solver 输出、metrics 和 checkpoint；

3. [经筛选的结果报告](../results/README.md)；
4. TODO 与研究计划；
