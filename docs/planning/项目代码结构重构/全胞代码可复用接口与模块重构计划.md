# 全胞代码可复用接口与模块重构计划

## 一、目标与非目标

本计划把 Full-cell 代码中重复的数学函数、职责过载模块和跨模块私有依赖，重构为可复用、可测试、可替换的公共接口。目标是让后续的统一 Fourier 潜在场、256 母版低通、多分辨率内容哈希、MPB 收敛和新数据生成复用同一套基础能力，而不是再次复制函数。

本计划属于 **L4 实现层重构**。它不改变：

- B/G 现有随机分布、seed、结构参数和拒绝规则；
- `FullCellStructureSpec` 的物理含义；
- HDF5 schema、字段内容、sample ID、geometry hash 或 split；
- MPB 材料函数、resolution、k 点、能带顺序和标签；
- 模型名称、checkpoint identity、训练超参数和指标；
- 任何已有实验结论或准入状态。

统一 Fourier 新算法和 256→128/64/32 新栅格合同由[数据验证计划](../数据验证/README.md)负责，必须在本重构完成后以独立配置、独立测试和独立提交实施。

## 二、当前问题基线

截至 2026-08-17，项目内至少有五个不同职责的 `full_cell.py`：

| 模块 | 当前规模 | 主要职责 | 主要风险 |
|---|---:|---|---|
| `phc2d.data.full_cell` | 约 555 行 | 解析结构、材料评价、栅格、HDF5 读写与流式写入 | 数据模型与基础设施耦合 |
| `phc2d.generators.full_cell` | 约 450 行 | B/G 随机结构、审计统计和拒绝采样 | 与 data 层重复 Fourier/网格逻辑 |
| `phc2d.solvers.full_cell` | 约 302 行 | Full-cell MPB band/eigenfield 与 oracle | 名称含糊，但职责相对集中 |
| `phc2d.forward.full_cell` | 约 962 行 | 配置、Dataset、训练、评估、画图与 CLI | 职责过载，私有函数成为事实公共 API |
| `phc2d.models.catalog.full_cell` | 约 222 行 | Full-cell 模型目录与懒工厂 | 与前四者同名但领域不同 |

当前可直接验证的重复和耦合包括：

- [`data/full_cell.py::_fourier_field`](https://github.com/fangtoast/phc2d/blob/master/src/phc2d/data/full_cell.py) 与 [`generators/full_cell.py::_field_from_modes`](https://github.com/fangtoast/phc2d/blob/master/src/phc2d/generators/full_cell.py) 分别实现同一 Fourier 求值；
- `forward/full_cell_cross_eval.py`、`full_cell_50k_evaluation.py`、`full_cell_final_test.py` 和 `full_cell_upgrade_50k_evaluation.py` 直接导入 `_FullCellH5Dataset`、`_evaluate`、`_forward_model` 等私有符号；
- `data/full_cell.py` 同时承担纯数学、领域模型、并行 raster 与 HDF5 IO；
- 当前模型包已有“实现模块 + 薄兼容 facade + identity 测试”的成功模式，但 Full-cell 数据/训练模块尚未建立对应架构门。

同名文件不会在 Python 中产生运行时冲突，因为完整模块路径不同；问题主要发生在阅读、搜索、日志、文档引用和职责扩展。因此不以“全部改名”为目标，而以“职责名明确、旧路径兼容、公共接口唯一”为目标。

## 三、重构设计原则

### 3.1 单一权威实现

同一个公式、序列化规则、hash 规则、栅格坐标或评估指标只能在一个模块实现。其他模块必须导入它，不允许复制后轻微修改。

新增公共函数前必须执行：

```text
按概念和公式搜索现有实现
  → 确认权威模块
  → 扩展公共接口与测试
  → 调用方复用
```

禁止新建含糊的 `common.py`、`utils.py`、`helpers.py` 或 `_common.py`。文件名必须说明领域与职责，例如 `full_cell_fourier.py`、`full_cell_raster.py`、`full_cell_io.py`。

### 3.2 依赖方向

目标依赖关系冻结为：

```text
纯数学与轻量类型
  ↓
解析结构与材料评价
  ↓
栅格 / 哈希 / HDF5
  ↓
生成器与求解器适配器
  ↓
训练 / 评估 / inverse / plot / CLI
```

反向依赖禁止：

- data 基础模块不得导入 generators、solvers、forward、inverse 或 plot；
- 纯数学模块不得导入 h5py、SciPy、Torch、Meep 或 MPB；
- solver 不得依赖训练 runner；
- plot 不得成为数据生成的权威实现；
- 基础 CLI help 不得触发 Torch、h5py、SciPy、Meep 或 MPB 导入。

### 3.3 稳定公共 API 与薄兼容层

历史模块路径先保留：

```text
phc2d.data.full_cell
phc2d.generators.full_cell
phc2d.solvers.full_cell
phc2d.forward.full_cell
```

迁移后这些文件只负责导入、重新导出和必要 CLI 委托，不再保留重复实现。兼容层中的对象必须与新实现对象保持身份一致：

```python
from phc2d.data.full_cell_spec import FullCellStructureSpec

__all__ = ["FullCellStructureSpec"]
```

禁止通过修改 `__module__` 伪造历史身份。若 pickle、checkpoint 或 artifact metadata 依赖模块路径，必须用显式稳定 identity 和 round-trip 测试处理。

### 3.4 公共与私有命名

- 被两个及以上生产模块使用的能力应提升为无下划线公共 API；
- 下划线符号只能在定义模块内部或其白盒单测中使用；
- 公共函数参数和返回值使用 dataclass、Protocol、Mapping 或具名结果，不依赖位置不明的 tuple；
- shape、resolution、band 数和字段名来自 metadata/config/spec，不新增长期硬编码；
- 公共 API 必须有简短 docstring，说明输入、输出、单位、可变性和异常。

## 四、目标模块布局

### 4.1 Data：解析结构与数据表示

```text
src/phc2d/data/
├── full_cell_fourier.py   # Fourier mode、坐标与纯 NumPy 求值
├── full_cell_spec.py      # FullCellStructureSpec 与材料评价分派
├── full_cell_raster.py    # 网格、raster pyramid、低通/面积平均接口
├── full_cell_hashing.py   # canonical serialization 与内容哈希
├── full_cell_io.py        # HDF5 schema、reader/writer/streaming writer
└── full_cell.py           # 历史公共导入 facade
```

`full_cell_spec.py`只定义领域对象和解析评价，不读取文件；`full_cell_io.py`只负责存储，不重新实现材料公式；`full_cell_raster.py`只调用结构对象的公共评价接口。

### 4.2 Generators：参数采样与接受规则

```text
src/phc2d/generators/
├── full_cell_binary.py    # polar/spectral binary 参数采样
├── full_cell_graded.py    # graded RBF/Fourier 参数采样
├── full_cell_stats.py     # 连通性、最小特征、频谱等审计
└── full_cell.py           # 历史生成器 facade
```

生成器只产生 `FullCellStructureSpec`，不拥有材料公式的第二份实现。结构统计通过 `spec.evaluate_material_weight()` 或 raster 公共接口获得数据。

### 4.3 Solvers：MPB 适配器

当前 `solvers/full_cell.py`职责相对集中，第一阶段可以保留。若后续确需拆分，目标为：

```text
src/phc2d/solvers/
├── full_cell_mpb.py       # Full-cell band/eigenfield MPB adapter
├── mpb_oracles.py         # uniform/circular-hole 数值 oracle
└── full_cell.py           # 历史 solver facade
```

是否拆分 solver 由行级职责和调用图决定，不为了目录对称而机械拆分。

### 4.4 Forward：数据适配、模型调用与 runner

```text
src/phc2d/forward/
├── full_cell_contract.py  # 配置解析、metadata/schema 与 split 合同
├── full_cell_dataset.py   # Worker-safe HDF5 Dataset
├── full_cell_inference.py # forward dispatch、evaluate 与指标
├── full_cell_runner.py    # 单路线训练循环和标准运行产物
└── full_cell.py           # 历史 CLI/公共 facade
```

目标公共符号至少包括：

- `FullCellH5Dataset`；
- `resolve_full_cell_forward_contract(...)`；
- `forward_full_cell_model(...)`；
- `evaluate_full_cell_model(...)`；
- `run_full_cell_forward(...)`。

交叉评估、50k 评估、最终测试和升级评估必须通过这些公共接口复用，不再导入下划线符号。

## 五、首批可复用接口合同

### 5.1 Fourier 与周期网格

建议公共接口：

```python
def evaluate_real_fourier_field(
    x: np.ndarray,
    y: np.ndarray,
    modes: Sequence[Mapping[str, float | int]],
) -> np.ndarray: ...

def periodic_cell_centers(shape: Sequence[int]) -> tuple[np.ndarray, np.ndarray]: ...
```

合同要求：float64 内部计算、广播规则明确、mode order 不影响结果、缺失 cos/sin 的策略固定、周期坐标约定固定，并以手算模态和旧实现等价测试覆盖。

### 5.2 解析材料评价

`FullCellStructureSpec`继续作为稳定领域对象。family 到 evaluator 的分派从多分支 `if/elif` 改为显式只读注册表，但注册表只接受轻量纯函数：

```python
MATERIAL_EVALUATORS: Mapping[str, MaterialWeightEvaluator]
```

生成器注册和材料 evaluator 注册分离，防止 data 层反向依赖 SciPy 生成逻辑。未知 family 必须 fail-closed；不得静默落入某个默认 evaluator。

### 5.3 Raster 与多分辨率表示

建议返回具名对象：

```python
@dataclass(frozen=True)
class FullCellRasterPyramid:
    source_resolution: int
    grids: Mapping[int, np.ndarray]
    method: str
```

旧的直接点采样继续作为版本化策略；未来的 256 母版 block mean 作为新策略加入。两者不能共享含糊的默认值，也不能在重构提交中改变现有数据内容。

### 5.4 Hash 与序列化

建议公共接口区分：

```text
hash_structure_parameters(...)
hash_structure_geometry(...)
hash_raster_content(...)
canonicalize_structure_payload(...)
```

每个接口显式记录算法版本、dtype、shape、端序和量化规则。`geometry_hash`现有结果必须在纯重构阶段逐字节保持不变。

### 5.5 HDF5 Reader/Writer

把“打开文件、schema 检查、字段读取、streaming write”封装为公共对象或函数，但不把整个文件永久加载进内存。训练 Dataset 复用 reader 合同，生成 finalizer 复用 writer 合同。

至少公开：

```text
inspect_full_cell_hdf5(...)
load_full_cell_hdf5(...)
write_full_cell_hdf5(...)
write_full_cell_hdf5_streaming(...)
```

历史函数继续从 `phc2d.data.full_cell` 和 `phc2d.data` 导出。

## 六、分阶段迁移计划

### 阶段 0：冻结现状与公共面

1. 生成 source/import ledger：模块行数、定义、跨模块导入、`__all__`、CLI、测试和文档引用；
2. 冻结一组 B/G 结构及其 parameter vector、geometry hash、32/64/128 raster、epsilon 和 MPB solver input；
3. 冻结现有 HDF5 round-trip、模型 factory identity、checkpoint schema 和 CLI help；
4. 把生产模块导入的下划线符号列为待迁移 API，不立即删除。

产物是机器可检查的兼容基线，不改变源码结构。

### 阶段 1：提取纯数学公共接口

1. 新建 `full_cell_fourier.py`；
2. 用单一 `evaluate_real_fourier_field` 替换两份重复实现；
3. 提取周期网格和 wrapped coordinate；
4. 对固定输入验证旧/新输出逐元素一致；
5. 确认导入该模块不会加载 SciPy、h5py、Torch、Meep 或 MPB。

该阶段是后续新 Fourier 数据实现的前置门。

### 阶段 2：拆分 data 领域对象、raster、hash 与 IO

1. 先搬迁，不改变公式、字段、dtype 或 hash；
2. `data/full_cell.py`改为薄 facade；
3. `data/__init__.py`继续导出历史公共符号；
4. 固定样本的结构 JSON、geometry hash 与 raster hash 必须完全一致；
5. 旧HDF5能够由新reader读取，新writer输出通过旧loader合同。

### 阶段 3：公开 forward 共享接口

1. `_FullCellH5Dataset`迁移为`FullCellH5Dataset`；
2. `_forward_model`和`_evaluate`迁移为语义明确的公共函数；
3. cross-eval、50k evaluation、final-test和upgrade evaluation改用公共接口；
4. `forward/full_cell.py`只保留runner委托、公共重导出和`main()`；
5. 训练/验证指标、checkpoint、history和标准run产物保持一致。

### 阶段 4：拆分 generators，评估 solver

1. B/G采样和结构统计分离；
2. 生成器统一调用data层材料评价与raster接口；
3. `generators/full_cell.py`变为薄facade；
4. 根据真实调用图决定是否拆分solver oracle，禁止为了对称而拆分；
5. 全部历史导入和CLI继续可用。

### 阶段 5：启用新数据能力

只有阶段1–4全部通过后，才按[全胞新数据生成实现与64+64试点计划](../数据验证/全胞新数据生成实现与64加64试点计划.md)增加：

- 统一硬截止Fourier潜在场；
- 256母版与固定低通；
- 新内容hash和collision ledger；
- B/G各64样本星仪试点。

这一阶段是行为变更，必须使用新schema/config/dataset identity，不属于纯重构提交。

## 七、架构与兼容测试

新增 `tests/test_phc2d_full_cell_architecture.py`，至少覆盖：

### 7.1 Facade与身份

- 历史导入与新实现导入是同一个对象；
- facade只包含导入、`__all__`、兼容别名、短docstring和CLI委托；
- 禁止通过修改`__module__`伪造身份；
- 需要序列化的dataclass、factory和callable执行pickle round-trip。

### 7.2 依赖方向

- 用AST检查data纯模块不导入generators/solvers/forward/inverse/plot；
- `full_cell_fourier.py`和`full_cell_spec.py`不导入重依赖；
- 生产模块不得从其他Full-cell模块导入下划线符号；
- `phc2d --help`和`phc2d plot --help`在未加载重依赖时可执行。

### 7.3 数值与数据兼容

- 旧/新Fourier场、材料权重、epsilon和raster逐元素一致；
- 固定结构的JSON和geometry hash完全一致；
- B/G固定seed生成的参数、metadata和结构顺序一致；
- HDF5 schema、字段、dtype、shape、split与round-trip一致；
- MPB material callback对代表性坐标返回一致介电常数；
- forward固定batch的输出、损失和指标在浮点容差内一致；
- 历史checkpoint能够加载，model name/factory identity/fingerprint/state_dict不变。

### 7.4 防重复规则

架构测试应防止已知重复再次出现：

- Fourier求值只有一个生产实现；
- grid coordinate只有一个权威实现；
- geometry/content hash算法按版本集中定义；
-训练评估公共函数只有一个实现；
- 新生产调用方不得直接复制公式或重新创建同名私有helper。

不建议只以固定行数作为唯一质量门；行数可作为职责过载提示，最终以导入方向、公共面、重复实现和兼容测试为准。

## 八、验证矩阵

每个阶段先运行最窄测试，再运行完整回归。正式验收环境统一为WSL `Ubuntu` + conda `meep_env`：

```bash
PYTHONPATH=src python -m compileall src tests
PYTHONPATH=src python -m pytest -q tests/test_phc2d_full_cell_architecture.py
PYTHONPATH=src python -m pytest -q tests/test_phc2d_full_cell.py tests/test_phc2d_full_cell_generation.py tests/test_phc2d_full_cell_forward.py tests/test_phc2d_full_cell_convergence.py
PYTHONPATH=src python -m pytest -q tests/test_phc2d_model_architecture.py tests/test_phc2d_cli_architecture.py
PYTHONPATH=src python -m phc2d.cli --help
PYTHONPATH=src python -m phc2d.cli plot --help
PYTHONPATH=src python -m pytest -q tests
```

涉及MPB适配器搬迁时增加固定2+2结构的real-MPB smoke；它只证明新旧适配器数值一致，不新增数据或物理研究结论。

## 九、提交、回滚与停止条件

每个阶段单独提交，建议顺序：

```text
test: freeze full-cell architecture contracts
refactor: centralize full-cell Fourier primitives
refactor: split full-cell data contracts and IO
refactor: expose reusable full-cell forward interfaces
refactor: separate full-cell generator families
```

不得把以下内容混入重构提交：

- 新随机分布、新K值或新温度范围；
- 256母版和低通行为变更；
- MPB resolution或材料参数修改；
- 新训练实验、checkpoint、dataset、runs或图件全集；
- unrelated dirty-worktree内容。

任一阶段出现以下情况立即停止并保持旧实现为权威：

- geometry hash、sample ID、raster或HDF5内容漂移；
- checkpoint或factory identity不兼容；
-基础CLI开始依赖重环境；
- WSL定向测试或完整回归失败；
- facade产生循环导入；
- 需要同时修改L3科学合同才能让重构通过。

回滚以阶段提交为单位，不使用破坏工作区的reset/clean；未提交用户文件始终排除在暂存范围之外。

## 十、完成定义与人工理解门

本重构只有同时满足以下条件才算完成：

1. 重复Fourier和grid实现已收敛为单一公共接口；
2. data、generator、solver、forward的依赖方向有自动测试；
3. 生产模块不再跨模块导入Full-cell私有符号；
4. 历史模块是薄兼容facade，公共对象身份和导入路径保持；
5. 固定结构、HDF5、MPB callback、forward指标和checkpoint兼容测试通过；
6. WSL `meep_env`定向测试、完整测试、CLI与文档审计通过；
7. 每个阶段有独立、可回滚的Git提交；
8. 人工维护者能够说明公共接口、依赖方向、兼容边界和新增功能应放在哪里。

完成重构不等于新数据算法已经实现。剩余gate是基于新公共接口实施统一Fourier与256母版合同，再执行MPB收敛和B/G各64样本试点。
