# 全胞新数据生成实现与 64+64 试点计划

## 一、来源、目标与边界

本计划把导师提出的两份数据调整建议转化为可测试的实现与试点合同：

- [全胞数据分布与覆盖分析](../full_cell_forward_inverse_training/full_cell_dataset_distribution_coverage_analysis.md)
- [全胞介电常数内容哈希与碰撞设计](../full_cell_forward_inverse_training/full_cell_dielectric_hash_collision_design.md)

目标是在不启动正式大数据生成的前提下，实现统一周期 Fourier 潜在场、B/G 两种材料映射、稳定身份与内容哈希、以 256 为高分辨率母版的固定抗混叠多分辨率表示，并在星仪分别生成 **64 条 binary 和 64 条 graded 样本**，完成 real-MPB 标签与图件审查。

“64+64”表示两个路线各 64 个样本，不是 128 个 HDF5，也不是 64 个数据集。该试点只验证数据合同、实现、可运行性和样本形态，不证明分布覆盖充分、模型有效或可直接扩展到 50k。

## 二、依赖与执行顺序

本计划依赖[MPB 分辨率收敛与耗时验证计划](MPB分辨率收敛与耗时验证计划.md)冻结正式 solver resolution：

```text
数据合同与实现
  → 本地非 MPB 单测/小样本渲染
  → 星仪 8+8 solver smoke
  → MPB resolution 计划给出 R*
  → 星仪 B/G 各 64 正式试点
  → 本机 WSL 固定抽样复算
  → 人工查看图件并决定是否扩展
```

若 resolution 计划尚未完成，可以用 64 做 diagnostic smoke，但必须标记为 `provisional_resolution_64`，不得作为正式 64+64 标签合同。

## 三、拟冻结的数据生成方法

### 3.1 共同 Fourier 潜在场

两条路线共享：

$$
f(\mathbf x)=\sum_{0<\lVert\mathbf m\rVert\le K}
\left[a_{\mathbf m}\cos(2\pi\mathbf m\cdot\mathbf x)
+b_{\mathbf m}\sin(2\pi\mathbf m\cdot\mathbf x)\right],
$$

$$
a_{\mathbf m},b_{\mathbf m}\overset{\mathrm{iid}}{\sim}N(0,1),
\qquad
z=\frac{f-\operatorname{mean}(f)}{\operatorname{std}(f)}.
$$

初始候选使用硬频率圆盘和 `K=20`，但 `K=20` 只是待验证候选。正式 64+64 前应检查最小特征、频谱与 MPB resolution 收敛；任何变更都形成新配置版本和新 dataset identity。

为保证实值场，只保存一个确定的半平面独立模态集合，或者显式满足共轭对称；mode order、坐标约定和零模态处理必须进入 schema 与哈希。

### 3.2 B/G 材料映射

Binary 使用目标材料占比分位数：

$$
w_B(x,y)=\mathbf 1[z(x,y)\ge\tau_q].
$$

Graded 使用 logistic：

$$
w_G(x,y)=\frac{1}{1+\exp[-(z(x,y)-b)/T]}.
$$

- B 的主要样本级随机量：Fourier 系数、$K$、目标材料占比；
- G 额外包含温度 $T$，bias $b$ 通过固定二分搜索匹配目标材料均值；
- 初始范围沿用老师建议中的候选范围，但在实现配置中显式声明，不从本文文字隐式读取；
- B/G 使用相同 latent-field 生成机制，但 sample ID、lane 和映射参数独立，不强制一一配对。

## 四、256 母版与四种输入表示

物理真值仍是解析 `FullCellStructureSpec` 及其 `evaluate_material_weight/epsilon_at`；256×256 是高分辨率数值表示，不升级为解析真值。

每个样本先在 256×256 子像素中心求值，再通过固定面积平均得到：

| 字段 | 从 256 母版降采样 | 角色 |
|---|---|---|
| `material_weight_grid_256` | 不降采样 | 高分辨率表示与图件母版 |
| `material_weight_grid_128` | 2×2 block mean | 高分辨率消融 |
| `material_weight_grid_64` | 4×4 block mean | 主模型输入候选 |
| `material_weight_grid_32` | 8×8 block mean | 低分辨率消融，不反向限制 $K$ |

不得分别在 32/64/128 上重新点采样后声称它们来自同一低通合同。所有降采样从冻结的 256 母版直接计算，避免级联舍入差异。

对于 B 路线，低通后的中间值表示像素材料面积覆盖率，不表示真实介质变成 graded。为避免语义混淆，建议新增明确字段：

```text
material_area_fraction_grid_32
material_area_fraction_grid_64
material_area_fraction_grid_128
material_binary_grid_256
```

是否同时保留严格 0/1 的中心采样网格由人工决定；若保留，必须使用不同字段，不能覆盖面积平均主表示。G 路线可继续使用 `material_weight_grid_*`。

不建议重复永久保存可由 $w$ 与材料常数线性重建的全部 `epsilon_grid_*`；HDF5 schema 应记录重建公式和材料常数，并通过 round-trip 测试证明一致。

## 五、身份、种子与内容哈希

至少区分四类身份：

| 标识 | 输入 | 用途 |
|---|---|---|
| `sample_id` | lane、master seed、sample ordinal | 稳定逻辑身份 |
| `parameter_hash` | 规范化解析参数和 mode order | 检测参数完全重复 |
| `geometry_hash` | 规范化 `FullCellStructureSpec` | 解析几何身份 |
| `content_hash_r{R}` | 规范化后的各分辨率材料数组 | 检测表示层碰撞 |

实现不得只依赖当前 32 位派生 seed 作为唯一性证明。新的 `_stable_seed` 应使用 SHA-256 的至少 64 位确定性派生，并把算法版本写入 manifest；即使 seed 不同，仍须通过 parameter/geometry/content hash 检测实际碰撞。

浮点哈希必须冻结 dtype、端序、shape、量化规则、NaN 策略和字节序列化方式。B 的 0/1 母版可 bit-pack；面积分数和 G 权重应使用明确的量化或原始 float32 字节合同。split 必须按解析身份分组，任何 32/64/128/256 内容碰撞组不得跨 train/val/test。

## 六、建议代码改造范围

### 6.1 生成与数据合同

1. `src/phc2d/generators/full_cell.py`
   - 新增统一 Fourier latent-field 生成器和 B/G 映射；
   - mode 集合、系数、$K$、均值/标准差、阈值或 bias/T 全部可序列化；
   - 在 256 审计网格上执行有限值、标准差下限、材料占比和最小特征检查。
2. `src/phc2d/data/full_cell.py`
   - 扩展 `FullCellStructureSpec` 的新 generator family；
   - 保持 `epsilon_at` 解析评价供 MPB 使用；
   - 新增 256 母版和固定 block-mean 多分辨率栅格化；
   - 新增版本化 parameter/geometry/content hashes。
3. `src/phc2d/data/full_cell_generation.py`
   - 增加按 hash group fail-closed 的 split 与重复检查；
   - manifest 记录 raster contract、hash algorithm、resolution 来源和 collision ledger；
   - B/G 试点配置各固定 64 行 sample plan。
4. `src/phc2d/plot/`
   - 新增可复现的多分辨率样本画廊、频谱、统计分布和能带叠加图；
   - 图件读取 HDF5 与 manifest，不在绘图时重新生成结构。

新增共享能力继续放在 `src/phc2d`，研究配置放在 `configs/research`，可执行实验合同放在 `experiments/research`，星仪脚本放在 `jobs/`。

### 6.2 最小测试矩阵

- 固定 seed 的结构、系数、参数哈希和内容哈希可重复；
- worker 数变化不改变样本内容与顺序；
- Fourier 场实值、周期边界连续、标准化后均值约 0/标准差约 1；
- B 的 256 母版严格为 0/1，G 有限且位于 `[0,1]`；
- 256→128/64/32 block mean 与手工小数组 oracle 一致；
- 同一样本四种分辨率、解析结构和 Wh 的 sample ID 一致；
- hash 碰撞组不跨 split，重复记录进入 ledger；
- HDF5 schema round-trip、断点恢复、失败 shard 和 finalizer fail-closed；
- `phc2d --help` 不因 h5py、Torch、MPB 或绘图库缺失而失败；
- WSL `Ubuntu` + `meep_env` 下 compileall、定向测试、完整测试、CLI help 与 2+2 real-MPB smoke。

## 七、B/G 各 64 样本设计

两个独立配置分别固定 64 个样本、相同 master contract version 和不同 lane seed。建议按目标材料占比与形态复杂度做二维分层，而不是只按 sample ordinal 取前 64 个。

### 7.1 Binary 64

- 目标材料占比划分 4 个区间，每区 16 个；
- 每个区间覆盖低/中/高潜在场边界长度或频谱复杂度；
- 接受后记录实际面积占比、连通块、最小特征、边界长度和高频能量；
- 若某层反复拒绝，不静默用其他层补齐，先输出拒绝原因。

### 7.2 Graded 64

- 目标材料均值划分 4 个区间，每区 16 个；
- 每区交叉覆盖至少 4 个温度分位层；
- 记录实际均值、标准差、灰度区域比例、min/max、频谱能量和 bias 求解残差；
- 若 logistic 饱和导致有效灰度不足，记录失败，不在结果后修改温度范围。

试点不建立 train/val/test 性能结论；可以冻结 `48/8/8` 仅用于 schema 与后续小模型 smoke，但所有统计和画廊必须覆盖完整 64 条。

## 八、星仪部署与 real-MPB

### 8.1 预检

1. 代码、配置、测试形成范围化 Git commit；
2. 通过本机 SSH 别名 `xingyi` 部署到新版本目录，写入并核对 `DEPLOYED_GIT_COMMIT`；
3. 只读检查 `sinfo`、用户队列、磁盘和当前环境版本；
4. 默认 dry-run 生成 plan/job manifest；
5. 经单独授权后执行 B/G 各 8 条、全 81 k 点的 solver smoke；
6. smoke 失败即停止，不自动扩展至 64+64。

### 8.2 正式 64+64 试点

- 使用计划 1 选定的 MPB resolution $R^*$；
- `mesh_size=3`、TE、10 bands、band guard、`1e-7` 和 band order 与 resolution 实验保持一致；
- MPB 继续调用解析 `epsilon_at`，不读取 32/64/128/256 栅格作为材料真值；
- B/G 可各占一个固定 64 CPU 节点并行，也可按阶段 A 的资源证据降低并发；
- 不允许两个作业写同一个 run 目录；
- 只读监控，不自动重启、改参数或合并旧 shard；
- 集群完成后下载 manifest、HDF5、标准 run 产物和必要图件，核对 SHA-256。

运行前必须新增或扩展 Xingyi 作业脚本；现有 50k 脚本硬编码 50,000 行计划，不能直接冒充 64 样本试点脚本。

## 九、数据统计与必需图件

每条路线至少生成：

1. 64 个样本的 8×8 256 分辨率总览；
2. 代表性 16 个样本的 `32/64/128/256` 四列对照图；
3. B 的面积占比、连通块、最小特征、边界长度和频谱能量分布；
4. G 的材料均值、温度、灰度比例、min/max、标准差和频谱能量分布；
5. 32/64/128 相对 256 的 block-mean 重建差异与内容碰撞统计；
6. B/G 平均二维功率谱和径向功率谱；
7. 每个样本 10 条能带沿统一 full-BZ 路径或规定 k 点序列的曲线；
8. 按材料占比/均值分层的能带包络；
9. 异常样本页：最大高频、最小特征、最大跨分辨率差异、最大 solver 耗时与任何失败。

图题必须标出 lane、sample ID、geometry/content hash 短前缀、MPB resolution、模型栅格 resolution 和“cluster pending WSL acceptance”状态。

## 十、接受门与后续决策

### 10.1 工程门

- 所有相关测试在 WSL `meep_env` 通过；
- B/G 各恰好 64 个唯一解析结构，四种表示齐全；
- hash ledger、sample manifest、solver provenance、失败账本和标准 run 产物完整；
- 无 NaN/Inf、越界材料权重、band order 违规或跨 split 碰撞；
- 256→128/64/32 严格服从冻结低通合同。

### 10.2 物理与人工门

- MPB resolution 使用计划 1 已接受的 $R^*$；
- 集群结果经 WSL `Ubuntu` + `meep_env` 分层抽取 B/G 各 8 个结构、9 个代表 k 点复算；
- median/P95 replay MRE 使用提交前冻结的跨环境门限；
- 导师人工查看 B/G 总览、四分辨率对照、统计分布、频谱和异常样本；
- 人工确认 64×64 是否作为主模型输入、32/128/256 是否只作消融，以及 B 面积分数是否为主输入合同。

只有全部通过，才能提出 1k 或更大数据扩展计划。64+64 通过不授权 10k/50k，不证明数据分布覆盖完整，也不替代后续模型训练和 real-MPB inverse replay。
