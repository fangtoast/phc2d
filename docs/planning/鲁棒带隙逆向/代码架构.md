# 鲁棒逆向代码架构

**扩展最近的负责模块，不复制正向训练或 MPB 实现。** 已有探索性领域组件与测试，完整 campaign、CLI 和 P3–P5 正式工作流仍待实现与验证。返回[总计划](README.md)。

| 已实现的边界 | 作用与状态 |
|---|---|
| `frozen_band_adapter.py`、`robust_gap.py` | 冻结 checkpoint 推理与有限扰动共同带隙；不代表物理通过 |
| `fourier_search.py`、`fourier_feedback_proposal.py` | Fourier 候选搜索与可信范围提案；周期栅格几何约束为可选合同 |
| `direct_fourier_search.py`、`fourier_screen.py`、`direct_search_journal.py` | 直接物理搜索与代理共用初始群体和几何筛选；支持显式求解预算和单控制器日志重放，已通过真实 MPB 小规模 smoke。已记录结果可在同一冻结合同下重放；状态不明的求解必须外部对账，不自动重试。可选核验接口由调用方验证原始证据与决策输入，启用状态随合同冻结；调用方仍负责原始证据保存、资源账目和调度。尚无正式 P5 对照结果 |
| `feedback_evaluator.py`、`refinement_feedback.py` | 复用 MPB 带边加密，汇总扰动数值门与物理反馈；组级精度策略要求成员使用同一合同，并在升级时重新评估整组，尚未接入正式 campaign |
| `feedback_state.py`、`feedback_loop.py` | 候选预算、接受规则、待处理状态与恢复；已做受控测试与单候选真实交接预检，未完成多轮真实 campaign |
| `feedback_journal.py` | 单控制器的物理交接、多轮状态链与调度状态交叉核对，也可保存终止失败的调度记录；真实成功单轮可回放，多轮和失败恢复目前为受控测试 |
| `feedback_dispatch.py` | 提交前预留预算，跟踪提交不明、结果与调度结算；需要外部持久化、单控制器及原始证据核验，真实调度记录仅做离线回放 |
| `local_edge_correction.py` | 同合同、过数值门观测的局部上下带边残差拟合；单候选预检有接受与拒绝例，尚无可推广的在线成本收益证据 |
| `resource_ledger.py`、`hpc/slurm_accounting.py`、`design_metrics.py`、`design_evidence.py` | 预算预留、原始账单复算、同设计共同区间与按目标配对统计；物理证据入口会核验频谱、栅格、数值门和相对于所供名义记录的未见扰动。调用方仍需证明名义记录覆盖优化使用的全部扰动，并核实账单真实性、工作完整性、不可重排及排除成本；不替代正式 campaign 控制器 |
| `audit_*`、`jobs/` 中对应薄包装 | 探索性候选、梯度和 solver 评估；可对声明的粗筛子集核对身份，但不得用部分结果代替全批筛选。完整求解记录可生成逐来源物理组指纹，多 seed 汇总先检查全组门与身份，再按来源统计。原始账单真实性仍须外部核验；当前证据见[可用性审计](../../results/inverse/鲁棒带隙逆向可用性审计.md) |

## 复用与缺口

| 现有位置 | 复用内容 | 接入前要检查的缺口 |
|---|---|---|
| `src/phc2d/data/full_cell_spec.py`、`full_cell_raster.py` | 解析结构身份和命名栅格化协议 | 与训练 HDF5 原输入逐样本比对，不能任意重建 epsilon |
| `src/phc2d/inverse/surrogate_runtime.py` | 冻结代理适配思路 | 当前适配器依赖 GenerativeInverseConfig；新 checkpoint 的反归一化、材料输入和 k 身份需重新核验 |
| `src/phc2d/inverse/candidates.py`、`selection.py`、`objective.py` | 候选容器、筛选和目标运算 | 抽取无生成器依赖的稳定合同；不跨模块导入私有函数 |
| `src/phc2d/physics/bz_gap_refinement.py` | k 点周期处理和带边运算 | 稀疏输出与新增 k 求解的明确区分 |
| `src/phc2d/replay/gap_refinement.py`、`solvers/full_cell.py` | 求解、加密和数值检查 | 通用候选输入、缓存和不同精度结果隔离 |
| `src/phc2d/runs/`、`hpc/` 与 `jobs/` | 产物协议、部署和调度 | 新 campaign 接口；调度文件仅作薄包装 |

旧 `inverse/runner.py` 已超过模块规模警戒线，不向其堆叠新优化循环。模型模块继续只定义架构。checkpoint factory、架构指纹、state-dict 和旧 CLI 保持兼容。

## 后续职责边界

以下保留最初的职责示意，文件名不是当前实现清单；已实现的实际模块以上表和源码为准。

```text
src/phc2d/
  inverse/
    design_space.py          # 拟新增：参数边界、编码和可行结构
    frozen_band_adapter.py   # 已实现：当前正向权重的物理频率接口
    robust_gap.py            # 已实现：共同带隙、扰动集合目标
    search.py                # 拟新增：无梯度搜索与可选梯度策略
    calibration.py           # 拟新增：局部带边残差与可信范围
    optimization.py          # 拟新增：一步状态转换与预算检查
  workflows/
    inverse_campaign.py      # 拟新增：分阶段编排，调用领域接口
  data/                      # 扩展现有结构/周期几何操作
  physics/                   # 复用并扩展带边数值操作
  replay/                    # 扩展现有求解交接与复算
  cli/commands/inverse.py    # 懒加载接入新 action
experiments/research/        # EXP-INV-xxx 阶段协议
configs/research/            # 对应机器参数；smoke 放 configs/smoke/
jobs/                       # GPU 与 M9 的薄调度包装
tests/                      # 单元、合同、集成、重启与回归
runs/{yyyymmdd}/{experiment_id}_{YYYYMMDDHHmm}/
docs/results/inverse/       # 结论改变时建立有证据的结果页
```

文件名是责任提案，实施前再次搜索；能扩展现有抽象时不重复创建。同一职责初期可保留在一个小模块，只有实际复杂度需要时再拆。shape、材料参数、band/k 数量从 metadata/spec 读取；torch、h5py、MPB 均为可选或惰性依赖。

## 最小接口与数据流

| 接口（拟议） | 输入 | 输出 |
|---|---|---|
| DesignSpace | 参数、边界和表示版本 | 唯一结构定义、合法性指标、geometry hash |
| FrozenBandPredictor | 结构或合同化栅格；可选梯度请求 | 反归一化频率、固定 k 身份、checkpoint 身份 |
| RobustGapObjective | 多扰动上下带边、目标频率与带对 | 有符号裕量、共同区间和可行性 |
| PhysicalEvaluator | 结构、扰动、k/resolution 策略 | 逐 k 频率、带边、收敛状态、资源耗时 |
| Search / Calibration | 已验证锚点、历史与剩余预算 | 提案、预测收益、接受决定与下一状态 |

workflow → inverse 领域接口 → data/models/physics/solver 适配器；jobs/CLI → workflow。data 和 models 不反向依赖 workflow 或 run 路径。未通过数值门的结果保留诊断，不进入已验证最优表。

GPU 输出候选任务 manifest，M9 输出不可变结果 shard，控制器验证身份后合并。交接键至少包含 campaign/target/candidate/perturbation、结构 hash、求解配置 hash、代码版本；预测另附 checkpoint hash。缓存键包含 k 集合、resolution、材料与求解器身份，不跨精度误用。中断后恢复已验证历史、预算、随机状态和待处理任务；重复 shard 幂等合并，不重复收费求解。

## 配置与原始产物

配置分为 experiment、dataset/splits、checkpoint/representation、design_space、target、perturbations、search、calibration、solver/refinement、budget、execution/output。所有物理阈值和种子进入 resolved config；路径由部署配置提供，不写进模型。

run 保留标准 `run.log`、`run.meta.json`、`config.resolved.yaml`、`results.json`、`metrics.json`、`history.csv` 和 `figures/`。按需增加 targets/candidates/solver_tasks manifests、逐候选结果、谱数组、预算账本和恢复状态；字段必须带单位、精度等级、失败码和来源 hash。原始数据不复制进 Markdown。

拟议 CLI action 为 `inverse design-preflight`、`design-audit`、`design-optimize`、`design-evaluate`，其中 optimize 支持显式恢复。它们尚不可调用；P1 才决定最小 action 集并补帮助/合同测试。现有 `inverse train` 不能冒充新优化入口。

已有只读入口 `phc2d inverse feedback-inspect --directory <记录目录>` 可重新核验单轮交接；使用 `--initial-state <状态文件>` 并按时间顺序重复 `--round <记录目录>` 可重放多轮状态链。它不提交任务，也不独立验证初始锚点；单轮模式不验证之前的状态链。该入口不等同于优化 campaign。

## 运行窗口与结果展示

首版为 CLI + 可审计状态表，结果图由现有 plot 层导出；暂不建设独立 Web 服务。预期窗口内容如下，所有数值在运行后填入：

```text
Campaign | Experiment | Stage | Code/checkpoint identity
Target   | Seed | Model | GPU platform | CPU job | State
Proposed | Legal | Predicted | MPB completed/failed | Pending
Best predicted margin | Best verified margin | Common interval
Coarse/refined discrepancy | Resolution status | Unseen perturbation status
CPU core-hours | GPU-hours | Wall time | Budget remaining | Next gate
```

failed、blocked、数值未收敛、预算耗尽分别显示。预测最优与真实最优分列，不能用一个绿色“成功”掩盖尚未复算状态。
