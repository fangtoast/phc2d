## 已有能力与真实缺口

## 拟扩展的职责

| 负责位置 | 输入 → 输出 | 依赖方向与验证 |
|---|---|---|
| `data/` 的可微 Fourier/投影小模块（待命名） | 源 spec、可变参数、温度、栅格合同 → 软材料 tensor 与可重建硬 spec | 依赖 Fourier/材料语义；不读取 checkpoint/run；与 NumPy 几何和 FD 对照 |
| `inverse/` 的 sampled margin 与平滑目标 | 物理频率 tensor、TargetSpec、点集/场景 → 精确与平滑分数 | shape 来自元数据；覆盖负裕量、带序异常、空共同区间和稳定 logsumexp |
| `inverse/` 的梯度提案策略 | 已验证中心、冻结 predictor/残差、约束与预算 → 候选和完整轨迹 | 调 data/models 接口；不拥有 solver 或训练正向权重 |
| 局部残差拟合/求值接口 | 同合同观测 → 系数与版本；tensor 参数 → 双带边修正 | 回归可在 CPU/NumPy，求值用 tensor 保留参数图；不要让拟合反向贯穿历史 MPB |
| `workflows/` 的最小闭环服务 | spec/config、观测与阶段状态 → 提案、物理请求、接受决定和下一状态 | workflow → inverse → data/models/physics/replay；不向 data/models 反向注入运行职责 |
| `cli/`、`jobs/` | 研究配置 → workflow 调用/调度包装 | 惰性重依赖；参数解析和提交层不承载算法 |

这是一份接口责任提案，尚无新 CLI action 可执行。实现前再次搜索调用方；若最近模块已经提供该能力，就扩展而不重复创建。`models/` 只保留正向架构和 registry；checkpoint 是运行制品，不搬进模型代码目录。现有超大 `inverse/runner.py` 不增加新算法循环。

附件建议的 `core/geometry`、`forward/models`、`configs/optimization`、泛化 `utils` 等目录不直接落地。现有 `configs/research/`、`experiments/research/`、`src/phc2d/data/physics/replay/workflows/` 已承担这些责任；结构迁移需另提方案。本次没有代码或目录迁移。

## 首批验证与实施顺序

| 顺序 | 最小交付 | 所需验证 |
|---|---|---|
| 1 身份 | 新主模型、来源 8、normalizer/k/材料/栅格 manifest | 参考预测复现；识别门控与固定融合、原始与排序后谱 |
| 2 几何 | tensor Fourier 标准化与软投影 | 零编辑、不同系数、周期点、均值/总体标准差、软硬极限与参数 FD |
| 3 目标 | 精确及平滑标量裕量 | 带对索引、数值稳定、平滑偏差、负值与场景交集 |
| 4 梯度 MVP | Adam + 匹配方向 + 硬候选 MPB 请求 | [012](https://github.com/fangtoast/phc2d/blob/master/experiments/research/EXP-INV-012-梯度链条开发验证.md) 全部预注册候选、物理谱与费用完整 |
| 5 反馈 | 同温度仿射残差、现有信赖域和恢复 | 参数导数、秩不足回退、同版本增益、未来观测隔离与等预算消融 |
| 6 鲁棒及正式 | 可微偏移桥接、G×P 与三场景矩阵 | 实际几何偏移、同设计共同区间、未见扰动和独立 WSL 验收 |

沿用现有定向测试，包括 `test_inverse_frozen_band_adapter.py`、`test_inverse_input_gradient_audit.py`、`test_inverse_fourier_design.py`、`test_inverse_local_edge_correction.py`、`test_inverse_trust_region.py` 与 feedback 相关测试；新增测试只证明本次改变的参数化、平滑目标和校正导数合同。torch/h5py/MPB 保持可选或惰性导入。

## 资源按用途分层

| 层级 | 用途 | 资源和停止约束 |
|---|---|---|
| Windows | 编辑、阅读、静态诊断 | 不作正式工程或物理验收 |
| WSL Ubuntu / meep_env | 正式窄测试、单例准入、最终物理对照 | 使用本轮冻结数值合同；预算包含复核 |
| N40/N56 或适用本地计算设备 | 高频代理 forward/backward 与多起点 | 冻结硬件/精度；一 trial 不跨平台重跑冒充新重复 |
| M9 | 硬候选 MPB、带边加密、分辨率与制造场景 | 明确尝试数、实际分配核时、内存和并发；每层成本单列 |

先运行固定温度的名义 MVP，不在首批请求中加入残差训练、三制造场景或大规模重训。来源 8 的预算建议见 012；后续阶段各自冻结资源，不继承旧 011 的 12 次/100 核时。

历史秒数只适用于对应硬件、k 点、分辨率和求解范围。新阶段以首例实测估算总额，记录几何准备、forward/backward、残差拟合、MPB 和审查费用。GPU 可在外层等待时释放，通过状态保存交接；已有预算、日志、缓存和恢复能力优先复用。

## 证据与恢复合同

配置按 experiment、source/dataset/splits、checkpoint/representation、design_space、target、smoothing、optimizer、feedback、perturbations、solver/refinement、budget 和 execution 组织。没有冻结具体权重和阈值以前，协议不能被包装为可提交 YAML。

标准产物写入 `runs/{yyyymmdd}/{experiment_id}_{YYYYMMDDHHmm}/`：`run.log`、`run.meta.json`、`config.resolved.yaml`、`results.json`、`metrics.json`、`history.csv` 和按需 `figures/`。增加以下有区分力的记录：

| 记录 | 必要字段 |
|---|---|
| 梯度与轨迹 | 参数/归一化坐标、温度/平滑版本、原始及平滑分数、梯度、实际位移、软硬几何/谱 hash |
| 物理观测 | 候选与场景身份、solver/k/resolution/材料合同、原始谱、数值门、失败原因及资源 |
| 残差 | 拟合可见观测列表、软/硬分支、系数/秩/条件数、版本和下一点的拟合前预测误差 |
| 决策与账本 | 本轮中心/候选的冻结预测、真实增益、比值、接受/拒绝、历史最优、在途任务和费用 |

缓存键包括几何、材料、k、分辨率、求解器、模型和投影版本，梯度路径不缓存 detached 结果。重复硬栅格保留提案事件，明确缓存与费用；不得默默替换成其他候选。中断恢复需重建随机状态、optimizer、平滑/残差版本和在途预算；提交状态未知先对账，不自动重复求解。

只有证据改变科学结论或 gate 时，才在 `docs/results/inverse/` 建立简短结果页并链接原始 run；普通日志不写成长期 Markdown。本次仅对文档进行验证，不宣称上述代码或实验已经通过新路线验收。
