# 逆向研究推进与交付

**项目交付两条可复现的设计路线：纯代理基线，以及可微代理与 MPB 反馈校正结合的方法；再将两者用于制造鲁棒设计。** 本页管理阶段、依赖和交付，数学与算法见[纯代理方法](纯代理方法.md)和[代理校正与微调](代理校正与微调.md)，具体比较见[实验与复核](实验与复核.md)。

## 工作包与执行顺序

| 工作包 | 输入与主要工作 | 可审阅交付 | 进入下一阶段的最小依据 |
|---|---|---|---|
| WP0 研究基线接入 | 固定融合 3×3 GL、来源 8、结构与输入合同；复用适用的 checkpoint 与 solver 检查 | 一份模型/来源/表示清单、参考预测和可调用求解入口 | 同一源结构可重建、参考预测可复现；只修复本次接入差异 |
| WP1 可微设计器 | tensor Fourier、总体标准差、Sigmoid、目标梯度和 Adam；保持硬几何语义 | 独立参数化/目标/优化接口、窄测试、完整 GL 轨迹 | 参数 AD–FD 一致，硬几何合法，设计过程可完成并保存 |
| WP2 MVP 与纯代理基线 | EXP-INV-012 单来源链路；随后 EXP-INV-013 的随机/DE/Adam、多起点与维度比较 | 锁定 Top-1、MPB 末尾结果、成功/失败和成本表 | 012 链条可解释；013 明确纯代理在多来源的真实能力，无需预先取得漂亮的成功率 |
| WP3 MPB 代理校正 | EXP-INV-014，批量物理观测、局部带边残差、校正后继续梯度优化、必要轨迹控制 | 纯代理/接受拒绝/校正三组及关键黑盒对照；逐轮误差、真实裕量和费用 | 完成同条件、同预算口径的比较；根据收益确定后续方法版本 |
| WP4 制造鲁棒 | EXP-INV-015，周期偏移、名义/平均/最坏目标；对纯代理和校正代理比较 | 三场景硬几何、共同目标区间、名义代价与未见扰动结果 | 每个场景达到统一数值标准，比较矩阵完整 |
| WP5 独立测试与成果 | EXP-INV-016，冻结版本、多目标/来源/seed，独立数值审查与全成本 | 主表、六图、复现包、方法稿和失败分析 | 证据覆盖目标主张，结果与论文相符，人工审阅成果 |

整体状态：规划已整理，WP0–WP5 的新路线交付尚未完成。现有源码和旧实验可按[现有基础](现有基础与复用.md)接入，不把“旧方案被取代”理解成重新实现所有能力。

WP0 与 WP1 可交叉推进；纯代理链路完成后，WP3 的样本/校正接口与 WP4 的几何扰动接口可以独立准备。正式鲁棒比较使用 WP3 已确定的方法版本。WP5 的图表脚本、结果 schema 和论文骨架从 WP2 开始准备，随证据填充；不等待全部实验结束才组织成果。

## 当前首先交付什么

第一批工作限定为来源 8、TE B4–B5、目标 0.57、两个结构参数。按 [EXP-INV-012](https://github.com/fangtoast/phc2d/blob/master/experiments/research/EXP-INV-012-梯度链条开发验证.md)先安排原点链路子批：GL 完成设计与候选选择，再进行末尾 MPB 检查。12 组或完整 48 组的选择在执行配置中一次确定，新增反馈阶段不占用这批的独立评价结果来追改选择。

来源 8 用于调通机制，来源 491、348 可在后续开发中覆盖不同初始裕量。多来源正式清单在方法开发后确定，不从已观察正例中组成测试集。WP2 以后按数据、样本量、实际成本选择下一批规模。

## 一次检查对应一次交付

| 何时检查 | 检查内容 | 如何继续 |
|---|---|---|
| 新接口或行为发生变化 | 最小单元/合同测试、真实源结构对照、适用 WSL 回归 | 通过即集成到下一批运行，不另造同义的预检层 |
| 首次接入某模型/表示/平台 | 来源与参考输出、实测显存/内存/吞吐、一次求解合同检查 | 保存身份和适用范围；后续相同合同直接复用 |
| 一批求解完成 | 清单覆盖、数值门、锁定选择、成本与失败分类 | 形成方法判断，继续已授权的下一工作包 |
| 阶段效果混合或为负 | 检查能区分原因的最小问题，如软硬投影、采样或梯度失配 | 明确是否修复、新版本或接受有限适用范围；不重复无区分力的检查 |

代码、数据、配置和环境未变且原证据适用时不重做验证。历史缺失只补会影响当前实验判断的部分。数值失败不能冒充无带隙；普通工程失败应修复后继续。本研究依次保留梯度、设计质量、物理误差、成本四类判断，不把一个不利指标视为整条路线停工的理由。

## 每阶段的资源与责任

阶段配置给出候选上限、每候选场景、k/分辨率策略、求解次数、CPU/GPU/WSL 总额度、并发/内存、墙钟和重试范围。先用已有同合同计时或一例实测估算，再安排批次；历史秒数与旧 011/012 的额度不自动继承。

| 角色/资源 | 责任 |
|---|---|
| fangtoast / 科学负责人 | 目标与比较对象、方法选择、阶段资源和最终科学判读 |
| 研究执行者与代码维护者 | 共用实现、实验配置、运行、数值诊断、复现和源码提交 |
| AI 协作 | 在授权内实现、验证、集成和交付，发现实际阻碍时给出具体解决路径 |
| N40/N56 或适用本地设备 | 代理推理/梯度、适配训练、多来源分片；每个 trial 保留唯一身份 |
| M9 | 候选批次 MPB、带边加密、resolution 与制造场景求解 |
| WSL Ubuntu / meep_env | 正式工程检查与阶段规定的物理复核 |

资源到账和数据就绪后继续已授权阶段。新增或扩大计算范围时，先提供可执行配置、额度和停止条件，再落实授权。本轮是规划整理，不提交远端计算。
